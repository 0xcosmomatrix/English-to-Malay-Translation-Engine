§1Verdict

The improvement is real and independently verified. The machinery that produced it is prototype-grade, and the review proved both halves of that sentence.

The data held. Every reported number reproduced exactly from disk. All 13 fresh dictionary lookups confirmed the PRPM ledger. All 193 enforce-tier entries carry complete provenance and pass the three-leg gate clean.

The machinery fell. Reviewers found 5 new correctness bugs in the pipeline code (2 critical), 5 ways to bypass the enforcement gate (3 critical), and — worst — that nearly everything except the rules directory lived in wipeable session storage, outside version control.

§4What this does not establish

  • Register is still the ceiling. ~28 of 43 reviewer flags are register calls no model reliably detects (best arbiter recall: 51%). Remediation with answers shown reaches ~50%; prevention from examples measured at zero.
  • No native speaker has read any of today’s output. Lexical claims are dictionary-verified; register claims are machine-plus-my-judgment only.
  • One chapter, one run, one book, one language pair. Differences of 1–2 checks between configs sit inside noise.
  • 168 of 193 enforce rules rest on dictionary absence plus panel unanimity — solid, but weaker than the 25 carrying the explicit “Id” label.

§5Road to autonomous near-perfection

phase 0 · durability — partially done today

Make the build survive its authors

Commit ms-MY-lab/ and move rules/ into the repo; fetch the full English bundle into the corpus registry. Until this lands, every other phase is building on sand.

phase 1 · correctness

One canonical pipeline, five bugs dead

Fix the five verified bugs; collapse pipeline / regate / gate_v3 into a single module so fixes can’t strand in siblings; make the fact check bidirectional (inventions penalized, not just omissions); re-run chapter 1 and confirm the numbers survive the fixes.

phase 2 · enforcement integrity

Close the gate’s own gates

Fail-closed corpus leg (missing corpus = gate failure); panel provenance must reference the stored verdict files, never default; a checksum manifest over enforce tier + ledger, verified at use time so direct edits are caught when they matter; replace --force with a ruling file; run enforce_gate --check in the build pipeline beside EPUBCheck.

phase 3 · coverage

From one chapter to the whole shelf

Run all 10 chapters + workbook through the fixed pipeline with per-chapter reports — the first fully instrumented book, and the evidence base scaling from anecdote to statistics.

phase 4 · the register flywheel

Make every native hour multiply

Retrieval-matched exemplars (the untested middle between fixed few-shot and nothing); the 43 flags as a growing regression suite gating every pipeline change; sampled native audit — one chapter per book, corrections feeding rulebook and exemplar bank; the phraseology layer (collocations, English-idiom calque prevention, figurative licence check) built through the proven harvest → panel → oracle → tier pipeline.

phase 5 · the compounding loop

Every book makes the system stricter

Each shipped book joins the approved corpus, strengthening the context-free leg automatically; each correction becomes a permanent rule or exemplar; the eval suite means no change ships on faith. Checkability grows with output — the system scales like a test suite, not like a model.
